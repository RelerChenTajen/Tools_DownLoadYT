把 YouTube 變成一樣大聲的 MP3

貼一個網址進去，出來一個 320 kbps、音量固定在 97、名字整齊的 MP3。就這樣。

它保證三件事

每一首出來都長一樣

拿最好的聲音

YouTube 有好幾條音軌，它永遠挑最高品質的那條（通常是 Opus 約 150 kbps），再壓成 320 kbps MP3。

一樣大聲

每首歌的音量都調到 MP3Gain 讀值 97.0。放進播放清單不用一直轉音量鈕。

名字整齊

檔名和 ID3 標籤一律「演唱者 - 曲名」，還附上封面圖。

裡面發生什麼事

五個步驟，一氣呵成

重點在第 3～5 步：量音量、調音量、壓成 MP3 是在同一次轉檔裡做完的，聲音只被壓縮一次。

1

找到影片

yt-dlp 去 YouTube 問：「這個網址有哪些音軌？」YouTube 會出一道 JavaScript 小考題，交給 Node.js 解。

2

只拿聲音，不拿畫面

抓最高品質的音軌（Opus 格式，幾 MB 而已），影片畫面完全不下載，所以很快。

3

量一下有多大聲

ffmpeg 用 ReplayGain 演算法（跟 MP3Gain 一模一樣的尺）聽完整首歌，算出「現在是幾 dB」。

4

算差多少，補上去

目標 97，現在 94.5，差 2.5。轉檔時就把音量加 2.5 dB。太大聲的歌則往下減。

5

壓成 MP3，貼上名牌

320 kbps MP3，寫入演唱者、曲名，把影片縮圖當封面塞進去。存到 output/。

為什麼是 97

你舊的 MP3 就是 96.6

MP3Gain 用 89 當「標準音量」，數字越大越大聲。你手上的收藏在 96～97 之間，所以新下載的也對齊到 97，前後不會突然一大一小。

Volume = 89 − ReplayGain gain

MP3Gain 只能一次調 1.5 dB，這個工具是在轉檔前用小數點精準調整，實測誤差 0.02 以內。

檔名怎麼來的

先問 YouTube，再拆標題

YouTube 偶爾會直接給演唱者和曲名，有就用。沒有的話就拆標題：先丟掉 (Official Video)、[Lyrics]、| HD 這類字，再從「 - 」或「【 】」切成兩半。

都切不開？頻道名當演唱者、整個標題當曲名。這種情況偶爾要手動改名。

跳出黑視窗，貼上網址按 Enter，等它跑完。

命令列
python yt2mp3.py "https://www.youtube.com/watch?v=xxxx"
--no-volume不調音量，保留 YouTube 原本的大小聲
--no-limit拉高音量後不壓峰值（可能削波）
-v 95改成別的目標音量
-b 192改位元率（預設 320）
--keep-original不轉 MP3，直接存 Opus 原檔（音質最好，但相容性差）
--list urls.txt一次下載很多首，每行一個網址
-o 資料夾改輸出位置（預設 output/）
用了哪些零件

四樣東西，都是免費的

yt-dlp負責跟 YouTube 講話、把音軌抓下來。YouTube 常改版，它也常更新。
ffmpeg聲音的瑞士刀：量音量、調音量、轉成 MP3、貼標籤和封面，全靠它。
Node.js幫 yt-dlp 解 YouTube 出的 JavaScript 考題，不然會缺格式。
Python把上面三樣串起來的 200 行腳本，就是 yt2mp3.py。
要知道的事

三個小提醒

推太大聲會自動壓峰值來源只有 91 的歌要推 +6 dB 才到 97，最高點會撞到天花板。腳本會自動加 limiter 把峰值壓住，音量仍對齊 97。想保留原本的動態就用 -v 95 或 --no-limit。
網址帶 list= 會抓整份清單從播放清單點進來的網址後面常有 &list=...，那會下載幾十首。只要一首就把它刪掉。
壞了先更新YouTube 改版時 yt-dlp 會失效。執行 python -m pip install -U yt-dlp 通常就好。

音質天花板永遠是 YouTube 給的那條音軌（約 150 kbps Opus）。320 kbps MP3 是為了「不再變差」，不是「變得更好」。只下載你有權使用的內容。
